# K-017 — Tablero principal y selección múltiple

Fecha: 2026-10-30. Completada.

Navegación lateral permanente de proyectos y tablero por defecto, con cinco columnas, tarjetas seleccionables, búsqueda, filtro por estado y solo bloqueadas. Chat y configuración de carpeta son vistas secundarias. Al borrar el proyecto abierto se abre el siguiente disponible.

El panel de detalle permite crear/editar título, descripción, criterios, orden y dependencias, cambiar estados manualmente, aceptar propuestas/resultados y consultar actividad, errores e intentos. Borrado con confirmación, respeto de versiones y restricciones del backend; errores conservando el borrador. Las operaciones no ejecutan agentes.

La selección permanece al inspeccionar, filtrar o visitar el chat; cambiar de proyecto la reinicia mediante el montaje por ID. Seleccionar/deseleccionar visibles conserva lo seleccionado fuera del filtro. El resumen enumera todas las seleccionadas, cuenta ocultas y distingue pendientes sin bloqueos, bloqueadas y otros estados. «Ejecutar seleccionadas» está deshabilitado y explica que seleccionar no autoriza ni inicia trabajo.

Sin cambios de backend, migraciones ni dependencias nuevas. Tres pruebas de lógica se incorporan al comando `npm run check` y se ejecutan por separado con `npm run test:board`.

## Comprobaciones realizadas

- `npm run test:board`: **3 pruebas correctas** sobre conservación de selección oculta y conjuntos anteriores, clasificación de seleccionadas/ocultas/eliminadas y combinación de filtros por texto, estado y bloqueo.
- `npm run build:desktop`: tipos y builds web/nativo correctos. Tras corregir la navegación al borrar el proyecto abierto se compiló la versión final y se comprobó exclusivamente ese caso adicional.
- Un recorrido UI automatizado en Chrome de pruebas sobre Ubuntu y el build web de producción: dos proyectos aislados, seis tarjetas iniciales con propuesta, tareas pendientes/bloqueadas, resultado en revisión, error y tarea hecha. Datos de QA en SQLite bajo `.tools/`; solo conector simulado.
- Selección con Espacio, apertura con Enter y cierre del detalle con Escape. Modal nativo HTML con etiquetas y controles accesibles. Seleccionar y deseleccionar visibles bajo búsqueda conserva las ocultas y sus nombres en el resumen; inspeccionar, guardar cambios y visitar el chat conservan la selección.
- Edición de título/descripción/criterios/orden; cambios manuales a en curso, revisión y hecha con comentario humano; desbloqueo de sucesoras únicamente al aceptar. Verificado por API que esos movimientos no crean intentos.
- Creación de tarea desde UI con dependencia y estado bloqueado, consulta de resultado/actividad guardados, conservación del chat anterior, cambio a un segundo proyecto vacío, creación de una tarea exclusiva y vuelta al primero con las tarjetas persistidas y selección vacía.
- Fallo de lectura inyectado una vez y recuperación mediante «Reintentar». Reinicio del backend y recarga de UI recuperan las siete tareas del primer proyecto. Ninguna petición de inferencia o ejecución; sin errores JavaScript.
- Capturas revisadas a 1100 × 850 y 640 × 640: sin desbordamiento horizontal de página, con desplazamiento propio de columnas. Las pruebas visuales usan el frontend en navegador; la compilación nativa se comprueba por separado.
- Caso adicional focalizado: borrar con confirmación el segundo proyecto de QA abre el primero y mantiene sus tarjetas.
- Revisión React: componentes separados por vista/tablero/detalle; estado acotado al ID del proyecto; peticiones con cancelación, tiempo límite y limpieza; derivados calculados durante render; inputs etiquetados, estados de carga/error, foco del diálogo y controles deshabilitados durante escrituras.
- `git diff --check`: correcto. No se repiten suites de API ni pruebas del selector de carpeta al no cambiar sus implementaciones.

## Repetir en escritorio

Iniciar API y escritorio según [desarrollo](../desarrollo.md). Abrir dos proyectos, crear tareas con una dependencia y seleccionar varias. Filtrar y abrir/cerrar un detalle: las seleccionadas ocultas deben seguir enumeradas. Guardar ediciones, cambiar al chat y volver; cambiar de proyecto debe vaciar la selección sin perder tarjetas. Aceptar una tarea en revisión debe desbloquear su sucesora. «Ejecutar seleccionadas» debe seguir deshabilitado.
