# K-002 — Proyectos persistentes

Fecha: 2026-10-29. Entorno: Ubuntu 24.04.4, sesión Wayland, Python 3.12.3, SQLite 3.45.1 y Node 22.22.2.

## Implementación

- SQLite mediante la biblioteca estándar de Python, sin dependencias nuevas. Archivo predeterminado: `.local/konsora.sqlite3`, relativo a la raíz del repositorio, independiente del directorio de arranque. La variable de entorno `KONSORA_DATABASE_PATH` permite elegir otro archivo.
- La primera operación de proyectos crea el esquema. Las migraciones y `PRAGMA user_version` se confirman en la misma transacción; los errores revierten los cambios. Una base corrupta o de una versión posterior produce un error sin reconstruirla ni sustituirla.
- Cada proyecto tiene UUID, nombre (1–120 caracteres tras recortar extremos), fecha de creación y última modificación. Los nombres admiten Unicode y no necesitan ser únicos.
- Las operaciones usan parámetros SQL y conexiones independientes. Los fallos de almacenamiento devuelven HTTP 503 con un mensaje controlado; la interfaz conserva los datos mostrados y el formulario para reintentar.
- La pantalla permite listar, crear, abrir, renombrar y eliminar. El borrado requiere un diálogo explícito; Cancelar y Escape lo cierran sin enviar ninguna petición de borrado. No se modifican los datos de la interfaz hasta recibir la confirmación del servidor.

## Contrato HTTP

| Método | Ruta | Resultado |
| --- | --- | --- |
| GET | `/projects` | Lista por fecha de creación descendente. |
| POST | `/projects` | Crea a partir de `{ "name": "…" }`, HTTP 201. |
| GET | `/projects/{id}` | Abre y consulta el proyecto. |
| PATCH | `/projects/{id}` | Renombra a partir de `{ "name": "…" }`. |
| DELETE | `/projects/{id}?confirm=true` | Elimina tras confirmación, HTTP 204. Sin confirmación se rechaza. |

Una identidad inexistente devuelve 404. Los nombres o parámetros inválidos devuelven 422. CORS sigue limitado a los orígenes locales del escritorio y permite las operaciones anteriores con JSON.

La suite de API incluye 31 casos: contrato de salud; ciclo CRUD y aislamiento entre proyectos; persistencia al recrear la aplicación; validación de nombres e identidades; confirmación del borrado; parámetros SQL; migración idempotente y rollback del esquema y de escrituras; bloqueos y recuperación; archivos corruptos; rutas no disponibles; protección frente a versiones futuras; configuración de la ruta y preflight CORS.

Se probó el flujo interfaz → API → SQLite → interfaz con una base aislada en `.tools/k002-verification.sqlite3`, sin utilizar datos personales:

- Chrome: crear, abrir, renombrar y eliminar; cancelar el borrado mediante botón y Escape sin peticiones DELETE; impedir nombres en blanco; recargar y conservar el proyecto.
- Bloqueo real de SQLite durante un renombrado: la API devuelve 503, el nombre original permanece guardado y el formulario conserva el nuevo texto. Al liberar el bloqueo, el mismo formulario permite guardar correctamente.
- Sin errores JavaScript ni peticiones fallidas imprevistas. Revisión visual a 1100 × 820 y 640 × 600, sin desbordamientos horizontales; diálogo usable con un nombre de 120 caracteres.
- Ubuntu nativo: abrir el proyecto, mostrar los diálogos de renombrado y borrado y cancelarlos. Tras cerrar y reiniciar tanto la API como el escritorio, el proyecto vuelve a aparecer y se abre con el mismo UUID y nombre. La inspección del escritorio se hizo mediante AT-SPI; el CRUD con entrada de texto se comprobó en Chrome.
- Binario de producción: lista y abre el proyecto persistido con Vite detenido, manteniendo la comunicación con la API local. Cierre correcto del proceso.

El aviso de deprecación HTTPX/Starlette de la suite inicial continúa visible. No afecta al resultado de las pruebas.

## Repetir la verificación manual

1. Iniciar la API y el escritorio con los comandos del README.
2. Crear un proyecto, comprobar que se abre y volver a la lista.
3. Renombrarlo; abrirlo de nuevo y comprobar el nombre.
4. Intentar eliminarlo y cancelar; comprobar que sigue en la lista.
5. Cerrar la aplicación y detener la API. Reiniciar ambos y abrir el mismo proyecto.
6. Eliminar únicamente ese proyecto de prueba, confirmando el diálogo; reiniciar y comprobar que ya no aparece.
7. Si la API se detiene durante una operación, comprobar el error, conservar el formulario y reintentar tras reiniciarla.
