# K-003 — Codex CLI con suscripción

Fecha: 2026-10-29. Ubuntu 24.04, Python 3.12, Node 22, Codex CLI 0.165.0 y sesión de ChatGPT.

**Completada:** un prompt enviado desde la UI obtiene `KONSORA_CLI_OK` de Codex real usando ChatGPT. No se utilizan claves ni facturación por API. Las pruebas automatizadas usan exclusivamente procesos ficticios locales.

## Implementación

- Interfaz tipada `AgentConnector` con consulta de estado y envío de prompt; implementaciones `MockConnector` y `CodexCLIConnector`. Sin dependencias nuevas: procesos, concurrencia, JSON y directorios temporales se gestionan con la biblioteca estándar de Python.
- Detección del ejecutable mediante `PATH` o `KONSORA_CODEX_BIN`. Se valida la familia **0.165.x** mediante `codex --version`; otras versiones se rechazan hasta revisar sus opciones. `codex login status` debe confirmar ChatGPT. Login por API, ausencia de CLI/sesión, configuración inválida y fallos de consulta tienen estados específicos.
- `KONSORA_CODEX_MODEL` es opcional y se valida en el backend. Si falta, se muestra «Predeterminado de Codex»; no se inventa un catálogo de modelos ni se considera que el login demuestre acceso a uno concreto. La inferencia real verifica el modelo elegido para ese turno.
- La UI inicia con Simulado, permite elegir Codex, muestra modelo/estado y conserva el prompt ante errores. Cada envío real exige confirmar la cuota. Consultar el estado no inicia inferencias. Cancelar aborta el request; el backend recibe la desconexión ASGI y termina el grupo de procesos.
- No hay persistencia de conversaciones, acceso a proyectos ni ejecución de tareas en K-003. Eso corresponde a K-004 y K-011.

## Contrato local

| Método | Ruta | Resultado |
| --- | --- | --- |
| GET | `/connectors` | `{id, name, status, model, detail}[]`, sin tokens ni salida cruda del CLI. |
| POST | `/connectors/{id}/prompt` | `{prompt, confirm_subscription_use?}` → `{connector, model, text}`. |

El prompt admite 1–16000 caracteres tras recortar extremos. Para Codex debe confirmarse explícitamente el uso de suscripción; sin confirmación devuelve 409 antes de invocar el CLI. No se aceptan campos adicionales, comandos, flags, rutas o URLs desde la UI. La validación no refleja el cuerpo de entrada. GET/POST de conectores rechazan hosts y orígenes ajenos a la UI local; POST exige JSON, además de CORS.

Los errores incluyen mensajes controlados: 503 para instalación/login/configuración no disponible, 401 para autenticación caducada, 429 para cuota, 502 para red/fallo del CLI/formato/herramientas inesperadas y 504 para timeout. Una consulta simultánea devuelve 409; no se encola ni reenvía automáticamente. Otros procesos locales no quedan autenticados por estas comprobaciones: la autenticación por sesión del servicio local sigue en K-012, antes de distribuir.

## Autenticación y permisos

Konsora no abre, copia ni exporta archivos de autenticación. El login se realiza manualmente mediante `codex login`; el CLI conserva y renueva su propio almacén. El proceso hijo recibe una lista mínima de variables del sistema y las rutas necesarias para su login, sin claves, tokens, proxies, URLs de API o variables internas del agente padre. No se cambia `HOME` ni `CODEX_HOME`.

Cada consulta ejecuta el CLI por argumentos mediante `create_subprocess_exec`, sin shell y con el prompt por stdin. No se introduce el prompt en la línea de comandos. Se utiliza un directorio temporal privado bajo `.local/codex`, sin archivos del proyecto, con un marcador `.git` para aislar la detección del proyecto padre. Se elimina al terminar, fallar o cancelar.

Opciones principales: `exec --ignore-user-config --ephemeral --json --color never --sandbox read-only --skip-git-repo-check --cd <directorio> -`. Se fuerza `forced_login_method="chatgpt"`, proveedor oficial, aprobación `never` y búsqueda desactivada. Se desactivan shell, snapshots, Code Mode, plugins, apps, hooks, subagentes, navegador, imágenes y otras herramientas. No se utilizan opciones para eludir el sandbox ni ampliar permisos. No se modifica la configuración personal del CLI ni se ignoran las reglas de ejecución. La configuración administrada del CLI sigue bajo control de su administrador.

Se limitan la ejecución a 120 segundos y cada flujo a 512 KiB. El supervisor elimina el grupo propio al cancelar, agotar tiempo/salida o terminar, incluyendo descendientes, y libera el bloqueo de concurrencia. Se procesa JSONL y solo se muestran mensajes finales del agente cuando existe `turn.completed`; diagnósticos no fatales de tipo `item.error` se omiten. Una notificación de herramienta inesperada se rechaza. Nunca se devuelven ni registran stdout/stderr crudos; se ocultan formatos conocidos de credenciales si aparecieran en el texto del modelo. El CLI puede mantener sus archivos operativos y de autenticación; `--ephemeral` evita guardar las sesiones de estas consultas.

## Repetición manual

1. Instalar el CLI oficial compatible y ejecutar `codex login`, eligiendo ChatGPT. No facilitar tokens a Konsora.
2. Iniciar API e interfaz como indica README. Probar Simulado sin cuenta ni consumo.
3. Elegir Codex; comprobar sesión y modelo. Si se cambió el login, actualizar conectores.
4. Introducir un prompt breve; comprobar que el botón permanece deshabilitado hasta confirmar cuota. Enviar y verificar la respuesta.
5. Durante una consulta, cancelar y comprobar el estado de cancelación. La cuota consumida no se recupera; no repetir envíos automáticamente.
6. Recargar y verificar que no se guarda conversación. Los proyectos de K-002 deben seguir disponibles.
