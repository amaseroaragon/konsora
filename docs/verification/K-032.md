# K-032 — Servicio local protegido

Verificado el 2026-10-31; comprobaciones de API/build web iniciadas el 2026-10-30.

- Autenticación Bearer aleatoria de 256 bits por instancia, comparación constante, cliente loopback, Host con puerto exacto y Origin permitido obligatorios. El middleware protege todas las rutas; los rechazos no devuelven datos ni secretos. Respuestas sin caché.
- El escritorio inicia su backend empaquetado en un puerto asignado por el SO. Rust entrega la clave por stdin y realiza las peticiones; el WebView solo usa IPC desde la ventana/origen local. No hay clave en JavaScript, URLs, argumentos o logs. El entorno del hijo se limpia de credenciales heredadas.
- Desarrollo web mediante proxy Vite `/api`, sesión privada 0600 y autenticación HTTP temporal; Host/origen del proxy también comprobados. Arranque documentado en `docs/desarrollo.md`; configuración antigua de proveedores retirada de `.env.example`.
- 106 pruebas API correctas, incluidas ocho nuevas de seguridad; tres casos del tablero correctos. Tipos/build web y build nativo release correctos. PyInstaller 6.22.3 empaqueta el servicio para evitar Python en la instalación final; reqwest permite el transporte privado desde Rust.
- Servicio empaquetado real: acceso autorizado correcto; lectura/escritura sin clave, con origen o Host incorrectos rechazadas; clave ausente de respuestas/stdout/stderr; cierre por EOF y puerto liberado.
- Escritorio Ubuntu 24.04, WebKitGTK y sesión Xvfb/DBus/XDG aislada: selector de carpeta → archivo externo → selección parcial → preparación → copia exacta al portapapeles GTK. El trabajo no seleccionado queda fuera. Cierre normal mediante WM_DELETE_WINDOW termina el proceso y su servicio. No se arrancó manualmente una API para este recorrido.

La automatización requirió adaptar los nombres accesibles de WebKit y la confirmación del selector; no fueron fallos del producto. Los avisos de portales/PipeWire del escritorio virtual no impidieron el flujo. No se tocaron los servidores personales en 8000/1420 ni sus datos. Esta autenticación separa clientes web/instancias; no pretende aislar procesos maliciosos con los mismos permisos del usuario.
