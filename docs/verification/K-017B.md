# K-017B — Tablero desde archivos

Completada, 2026-10-30. El tablero usa `.konsora/tasks.json` y muestra su origen; las tareas SQL anteriores son de solo lectura hasta migración explícita, con destino y conteos revisables. Se conservan todas sus filas/migraciones y no se sobrescribe un archivo existente. IDs, dependencias, actividad e instantáneas/resultados se trasladan al documento portable; una instalación limpia reconstruye el trabajo desde una copia de la carpeta.

Las lecturas no crean directorios, tareas ni claves. El tablero relee cada 2,5 segundos y al actualizar; cambios de contenido sin incrementar versión se detectan. JSON inválido/desaparecido conserva la última lectura visible sin habilitar escrituras. Los borradores se conservan al rechazar una revisión obsoleta y se pueden recargar explícitamente. Desvincular/borrar el registro de proyecto conserva archivos.

Acceso a metadatos por descriptores con `O_NOFOLLOW`, rechazo de enlaces duros/archivos especiales, bloqueo cooperativo de carpeta, temporal sincronizado y sustitución atómica. La inicialización no reemplaza destinos existentes. El [contrato](../formato-tareas.md) documenta la ventana residual de carrera con editores que ignoran el bloqueo; no se promete coordinación universal con ellos.

Un `done` externo se muestra en revisión. La aceptación UI firma su huella con clave privada fuera del proyecto; firmas falsificadas, cambios de contenido, carpetas copiadas y nuevas instalaciones requieren nueva revisión. Las claves propias de Konsora están ignoradas por Git y no se exportan. Si el almacenamiento local está dentro del proyecto, se rechaza la firma hasta configurarlo fuera; no se amplían permisos para resolverlo.

- Proyectos, carpetas e históricos anteriores: **43 correctas**. No se repiten conectores/inferencias.
- `npm run test:board`: **3 correctas**. `npm run build:desktop`: tipos y builds web/nativo correctos.
- Un recorrido UI sobre el build de producción, dos carpetas locales de QA y solo simulador: migración con vista previa, edición reflejada en el mismo archivo, aceptación humana, cambio por IA sin aumentar versión, selección conservada, conflicto manteniendo borrador, archivo inválido/perdido y recuperación. Sin errores JavaScript ni peticiones de agentes.
